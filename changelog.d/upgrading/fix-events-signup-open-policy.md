Migration `events.0026_signup_open_policy` adds the sign-up open policy (`signup_open_mode`, `signups_open_hours_before`) to events, series and org defaults. Every existing row gets manual mode and 72 hours, so nothing opens on its own until an organizer picks "immediately" or a number of days before start. Existing events keep their stored `signups_open_at`. Migration `events.0027_backfill_signup_open_policy` then switches every upcoming event that already has a `signups_open_at` to the days-before-start mode, with the hours taken from that stored time (rounded, between 0 and 1440), so the edit form shows the schedule the event will actually follow and "Open manually" can cancel it. Both run in the normal migrate step. Once a series is switched to "immediately", the next run of the open-signups beat task opens every upcoming event that series has already generated, and their announcements and sign-up posts go out.
